# gun — управление пушками Create Big Cannons (CC:Tweaked)

Наводит пушку и стреляет: один раз по координатам или постоянно, следя за движущейся целью. Работает сама по себе, радар не нужен. Цель может прийти откуда угодно: координаты в программе, другая программа, модем, радар.

## Установка одной командой (нужен HTTP в CC)

```
wget run https://raw.githubusercontent.com/cfifskin/gunLib/main/gun_disk/get.lua
```

Команда скачивает файлы из репозитория во временную папку, устанавливает библиотеку и удаляет временные файлы. Перезагрузка не нужна.

Сделать установочную дискету (файлы останутся на ней):

```
wget run https://raw.githubusercontent.com/cfifskin/gunLib/main/gun_disk/get.lua disk
```

## Справка на компьютере

После установки справка открывается как обычная тема CraftOS: `help gunLib`. Регистр букв важен. Стрелки вверх и вниз прокручивают текст, влево и вправо переходят между разделами, Q закрывает.

## Состав

На компьютер ставится только папка `gun_disk/`. В корне репозитория лежит то, что на компьютер не попадает: это описание и `tests/`.

| Файл в `gun_disk/` | Назначение |
|---|---|
| `startup.lua` | Автозапуск при загрузке компьютера с дискетой: ставит или обновляет библиотеку, затем запускает собственные startup-файлы компьютера |
| `install.lua` | Установщик. `disk/install` ставит или обновляет, `disk/install remove` удаляет |
| `uninstall.lua` | Удаление библиотеки |

| `loader.lua` | Ставится как `/startup/00_gunlib.lua` и делает `require("gun")` и `require("ballistics")` доступными из любой папки |
| `example_aim.lua` | Пример выстрела по координатам. Копируется в `/gun_aim_example.lua`, если такого файла ещё нет |
| `example_track.lua` | Пример слежения за целью с радара. Копируется в `/gun_track_example.lua`, если такого файла ещё нет. Только этому примеру нужна библиотека `radar` |

| `get.lua` | Установка с GitHub одной командой |

## Установка с дискеты

1. Скопируйте файлы папки `gun_disk/` на дискету: в мире это `saves/<мир>/computercraft/disk/<id>/`, где `<id>` выдаёт команда `id` при вставленной дискете.
2. Вставьте дискету в дисковод рядом с компьютером.
3. Перезагрузите компьютер (зажать **Ctrl+R**) или выполните `disk/install`.

## Удаление

```
wget run https://raw.githubusercontent.com/cfifskin/gunLib/main/gun_disk/uninstall.lua
```

С дискеты: `disk/uninstall`. Вместе с примерами: добавьте `all`. Библиотека `radar` при этом не затрагивается.

## Быстрый старт

```lua
local gun = require("gun")

local cannon = gun.bigCannon({
    mount = peripheral.find("cannon_mount"),
    offset = { 2, 0, -3 },                     -- блок лафета минус блок компьютера
    length = 8,                                -- блоков пушки перед затвором, до дула включительно
    muzzle = 5,                                -- блоков от блока над лафетом до дульного блока
    charges = { "powder", "powder", "mk3" },   -- заряды от затвора вперёд
    shell = "he_shell",
})
cannon:assemble()

-- Один выстрел по координатам: повернётся, дождётся наведения, выстрелит.
local state = cannon:fireAt(100, 70, -20)
print(state.fired, state.reason)
```

## Одиночная наводка

| Вызов | Что делает |
|---|---|
| `cannon:aimAt(x, y, z)` | Отдаёт команду лафету и сразу возвращается |
| `cannon:aimAt(x, y, z, { wait = true })` | Доводит ствол и возвращается, когда пушка наведена |
| `cannon:fireAt(x, y, z)` | Наводит и стреляет. `state.fired` показывает, был ли выстрел |
| `cannon:fire()` | Выстрел из текущего положения. Возвращает `true` или `false, причина` |

Вместо `x, y, z` можно передать цель: `cannon:fireAt({ x = 100, y = 70, z = -20 })`. Если у неё есть `velocity`, упреждение считается и здесь: `fireAt` стреляет и по движущейся цели.

Параметры последним аргументом: `arc`, `latency`, `timeout` (сколько тиков ждать, по умолчанию `gun.config.aimTimeout`).

Если цель недостижима или лафет не может её довести, ждать бессмысленно: `aimAt` с ожиданием и `fireAt` сразу возвращают причину в `state.reason`.

## Слежение за движущейся целью

```lua
cannon:follow(function()
    return getTarget()               -- { x, y, z } или nil, если цели сейчас нет
end, {
    onUpdate = function(state)
        if state.onTarget then cannon:fire() end
    end,
})
```

`follow` работает, пока не вызван `cannon:stop()`, пока `onUpdate` не вернул `false` или пока не вышел `timeout` (в тиках). Вызов блокирующий: рядом с другими задачами запускайте его через `parallel`. Несколько пушек — каждая своим `follow` в одном `parallel.waitForAll`.

Цель может быть:
- **функцией**, которая возвращает `{ x, y, z }` или `nil`. Вызывается на каждом шаге и может занимать время (например, `radar.scan`);
- **таблицей**, которую обновляет другая программа. Между обновлениями позиция продвигается по скорости.

Необязательные поля цели:
- `velocity = { x, y, z }` в блоках за тик. Без неё скорость оценивается сама, по позициям за последнюю секунду. На оценку нужно несколько шагов, поэтому точная скорость от источника лучше;
- `uuid`: при его смене история прошлой цели забывается. Без `uuid` то же самое происходит при скачке позиции, а вручную — через `cannon:reset()`.

Со своим циклом вместо `follow` вызывайте один шаг:

```lua
while true do
    local state = cannon:update(target)
    if state.onTarget then cannon:fire() end
    sleep(0.05)
end
```

Цель с радара (координаты должны быть мировыми, `global = true`, поля `velocity` и `uuid` у них уже есть):

```lua
cannon:follow(function()
    local targets = radar.scan(sensor, "sublevel", true)
    return targets[1]
end, { onUpdate = ... })
```

### Что возвращают `update`, `aimAt`, `fireAt`, `follow`

Таблицу `state`:

| Поле | Значение |
|---|---|
| `ok` | Есть решение и пушка может его выполнить. Иначе `reason` объясняет почему, а лафет остаётся на месте |
| `onTarget` | Снаряд, выпущенный сразу после этого вызова, попадёт. Учитывает, что ствол успеет довернуть за время до выстрела |
| `miss` | Ожидаемый промах такого выстрела у цели, в блоках |
| `error` | Насколько ствол отклонён сейчас, в градусах |
| `slew` | Сколько тиков лафету ещё поворачиваться |
| `yaw`, `pitch` | Углы лафета. На конструкции — в её осях. Соглашение CBC: yaw 0 = +Z, 90 = −X, 180 = −Z, pitch > 0 — вверх |
| `worldYaw`, `worldPitch`, `direction` | Направление ствола в мире |
| `ticks` | Время полёта снаряда |
| `aimPoint` | Где будет цель в момент попадания |
| `muzzle`, `carrierVelocity`, `arc`, `muzzleSpeed` | Точка вылета, скорость от конструкции, выбранная дуга, скорость снаряда |
| `target` | Предсказанная цель: позиция и `velocity`, в том числе оценённая |
| `mode` | Откуда взята позиция пушки: `ground`, `structure`, `manual` |
| `fired`, `fireError` | Только у `fireAt`: был ли выстрел и почему нет |

Значения `reason`: `no target`, `not assembled`, `out of range`, `pitch ... outside ...`, `projectile expires before reaching the target`, `mount shaft is not turning`, `timeout`, а также текст ошибки периферии или GPS. Ошибки внутри `update` не роняют программу, поэтому слежение переживёт, например, выгрузку чанка с лафетом.

## Описание пушки

| Функция | Параметры |
|---|---|
| `gun.bigCannon{...}` | `length`, `muzzle`, `charges`, `shell`, `muzzleBrakes` (дульные тормоза CBC: AT в конце ствола), `speed` (задать скорость вручную) |
| `gun.autocannon{...}` | `material` (`"cast_iron"`, `"bronze"`, `"steel"`), `barrels` (блоков автопушки перед затвором), `muzzle`, `round` |
| `gun.heavyAutocannon{...}` | то же, что у автопушки, плюс `strong = true` для усиленного патрона (×1.5 к скорости) |

Общие параметры:
- `mount`: лафет, обёрнутый или по имени. Без него работают только `cannon:solve` и `cannon:trajectory`;
- `offset = { dx, dy, dz }`: блок лафета минус блок компьютера. На конструкции Sable это оси конструкции. Таблицу может менять другой скрипт, она читается на каждом шаге;
- `position = { x, y, z }`: вместо `offset`, блок лафета в мире (F3). Только на земле, GPS не нужен;
- `arc`: `"auto"` (по умолчанию: настильная, а если она вне пределов наклона — навесная), `"low"`, `"high"`;
- `tolerance`: допустимый промах для `onTarget`, в блоках. По умолчанию 1;
- `limits = { мин, макс }`: пределы наклона, по умолчанию −30..60 у big cannon, −45..90 у автопушек;
- `pivotOffset`: где ось поворота относительно блока лафета, по умолчанию `{ 0, 1, 0 }`, блок над лафетом.

Заряды: `"powder"` (порох CBC, 2), `"mk1"`…`"mk5"` (CBC: ES, 2.5…4.5), `"cartridge1"`…`"cartridge4"` (большая гильза, 2 за уровень) или число. Снаряды: все снаряды CBC и CBC: ES, варианты Mk пишутся как есть (`"he_shell_mk3"`). У ES bunker buster своя баллистика, остальные Mk совпадают с базовыми. Патроны автопушки: `ap`, `flak`, `machine_gun`, `apds`, `apdsfs`, `he`, `hei`. Тяжёлой: `ap`, `apds`, `apdsfs`, `he`, `hef`, `heat`, `smoke`. Можно передать свою таблицу `{ gravity = , drag = , quadratic = }`.

Прочие методы: `cannon:assemble()`, `cannon:disassemble()`, `cannon:setFiring(true/false)` (держать спуск: автопушка стреляет, пока он нажат, только лафеты CC:CBC), `cannon:pivot()`, `cannon:setOffset(dx, dy, dz)`, `cannon:reset()`, `cannon:solve(target, opts)` (только расчёт, ничего не двигает), `cannon:trajectory(solution)` (точки полёта по тикам).

## Позиция пушки

| Режим (`state.mode`) | Когда | Как считается |
|---|---|---|
| `"manual"` | задан `position` | Координаты из описания пушки |
| `"ground"` | компьютер на земле | Блок компьютера плюс `offset`. Блок компьютера берётся из GPS (один раз) или из `gun.setHost(x, y, z)` |
| `"structure"` | компьютер на конструкции Sable | Один раз калибруется блок компьютера в координатах конструкции (GPS + поза), дальше позиция идёт из `sublevel.getLogicalPose()` на каждом шаге |

На конструкции нужен CC: Sable и GPS для калибровки. Компьютер и лафет должны стоять на одной конструкции. Если она двигалась слишком быстро, будет ошибка `structure calibration failed`: замедлите её и вызовите `gun.calibrate()`. Тот же вызов нужен после переноса компьютера.

## Лафеты

Библиотека определяет лафет по его методам:

| Периферия | Мод | Поворот | Выстрел |
|---|---|---|---|
| `cannon_mount` | CC:CBC | Плавный, сам, со скоростью вала | Уровень сигнала: `fire()` даёт импульс, `setFiring` держит |
| `cbc_cannon_mount` | CBC Peripheral, CC Optical | Мгновенный | Один выстрел за вызов |

Перед наводкой пушку нужно собрать: `cannon:assemble()`, иначе будет `not assembled`.

На лафете CC:CBC скорость поворота равна `обороты вала × 0.0375` градуса за тик: 256 RPM — 9.6°/тик, 64 RPM — 2.4°/тик. Без вращения на валу лафет не двинется, это покажет причина `mount shaft is not turning`. Вал должен крутиться с запасом: при слишком медленном повороте пушка не догонит цель, и `onTarget` не наступит.

CC Optical может запрещать свободный поворот тяжёлых пушек своим конфигом. Тогда текст его ошибки придёт в `state.reason`. Компактный лафет (`compact_cannon_mount`) не поддерживается: он умеет только наклон.

## Как считается упреждение

На каждом шаге `update`:

1. Цель приводится к текущему моменту: продвигается по скорости на возраст её данных. Скорость берётся у цели или оценивается наименьшими квадратами по позициям за `gun.config.velocityWindow` тиков.
2. Параллельно читаются лафет и поза конструкции: каждый такой вызов стоит игрового тика, и данные должны относиться к одному моменту.
3. Считается решение на момент вылета снаряда. Команда лафету и спуск занимают тики, и их число зависит от сервера, поэтому библиотека их измеряет сама. Если стволу нужно дольше повернуться, упреждение берётся на этот срок.
4. Цель и пушка в расчёте продолжают двигаться всё это время, снаряд наследует скорость конструкции.

Поэтому `cannon:fire()` нужно вызывать сразу после `update`, как в примерах: `onTarget` относится именно к такому выстрелу.

`gun.config`: `tolerance`, `latency` (добавочные тики упреждения сверх измеренных, если снаряд систематически отстаёт или опережает), `aimTimeout`, `velocityWindow`, `maxTargetSpeed` (блоков за тик; быстрее считается новой целью), `staleTicks`, `maxAge` (сколько тиков продвигать старую позицию), `gpsTimeout`, `structureCheck`.

## Баллистика

Физика повторяет код модов: Create Big Cannons 5.11, CBC: Enhanced Shells, CBC: Advanced Technology.

`ballistics.lua` можно использовать отдельно, ему не нужны ни `gun.lua`, ни периферия:

```lua
local ballistics = require("ballistics")
local profile = ballistics.bigCannon({ length = 8, muzzle = 5, charges = { "powder", "powder", "mk3" } })
local solution = profile:solve({ x = 100, y = 70, z = -20 }, { pivot = { 0.5, 65.5, 0.5 } }, { arc = "auto" })
```

Второй аргумент `solve` описывает пушку: `pivot`, `orientation` (кватернион конструкции), `velocity` (функция: скорость точки в блоках за тик).

Что учитывается:
- Начальная скорость big cannon. В CBC это сумма сил зарядов. CBC: AT по умолчанию заменяет её своей моделью «газов»: каждый блок ствола добавляет скорость и сопротивление, поэтому скорость зависит от длины пушки и от положения зарядов (`ballistics.bigCannonSpeed{...}` её считает). Если на сервере в конфиге cbc_at `disablePhysicRework = true`, поставьте `ballistics.config.physicsRework = false`.
- Скорость автопушки: `base_speed + speed_increase_per_barrel × min(стволы, max_speed_increases)` материала. Снаряд живёт `projectile_lifetime` тиков (у тяжёлой ×3), за этим пределом решения нет.
- Полёт: каждый тик `позиция += v + a/2`, `v += a`, где `a = гравитация − drag·v` (у тяжёлой автопушки `drag·|v|·v`). Для линейного сопротивления решение точное (замкнутая формула), для квадратичного — итерации Ньютона по симуляции.
- Точка вылета: у big cannon центр дульного блока, у автопушки — передняя грань последнего ствола.
- Конструкция Sable: углы пересчитываются в оси конструкции, а скорость точки вылета (`sublevel.getVelocity` + вращение) прибавляется к скорости снаряда, как делает CBC при `sableProjectilesInheritPhysicsObjectVelocity = true` (по умолчанию). Если на сервере выключено — `ballistics.config.inheritVelocity = false`.
- В Незере и Энде другая гравитация и сопротивление: `ballistics.config.gravityMultiplier` и `dragMultiplier`.

Не учитывается: случайный разброс выстрела, вода на пути, ускорение цели (считается, что она летит по прямой), поворот конструкции за время до выстрела, лафеты вверх ногами, минометы, ракеты и ракетные установки, спаренные автопушки. Проверить калькулятор в игре стоит выстрелом по неподвижной цели: если промах заметный, сверьте `length`, `muzzle` и конфиги сервера.

## Переход со старого `ballistics`

Раньше калькулятор поставлялся с радаром и брал позицию из него.

| Было | Стало |
|---|---|
| `ballistics.bigCannon({ offset = ... })` | `gun.bigCannon({ mount = ..., offset = ... })` |
| `gun:aim(target, opts)` + `ballistics.point(mount, solution)` | `cannon:update(target, opts)` |
| `radar.setHost(x, y, z)` для позиции пушки | `gun.setHost(x, y, z)` |

## Ограничения

- Чтобы `require` работал из любой папки, загрузчик регистрирует модули в `debug.getregistry()._LOADED`. Это внутренняя деталь CC:Tweaked. Если она изменится, загрузчик выведет подсказку, а в программе нужно будет добавить `package.path = "/lib/?.lua;" .. package.path`.
- Библиотеки загружаются один раз при старте компьютера. После обновления файлов в `/lib` нужна перезагрузка.
- Пока дискета вставлена, её `startup` заменяет startup компьютера. Скрипт с дискеты сам запускает `/startup.lua` и `/startup/*`, но после установки дискету лучше вынуть.

## Тесты

`tests/run.lua` на компьютер не устанавливается. Он выполняется на компьютере CC, куда скопирован вручную, рядом должны лежать `/lib/ballistics.lua` и `/lib/gun.lua`. Лафеты и CC: Sable в нём имитируются, время виртуальное, а снаряд летит по собственному интегратору теста. Настоящие лафеты в тестах не участвуют.
